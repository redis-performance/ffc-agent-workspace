# Change: ffc_loop_parse_if_eight_digits in parse.h
#   For __aarch64__ && __clang__ only:
#   - The original while(>= 8) loop is replaced with:
#       while(>= 16) { process val1+val2 as 2 independent SWAR blocks }
#       if(>= 8)    { process single 8-digit block (no back-edge) }
#   - GCC path: unchanged original while(>= 8) loop
#
# Analysis:
# The −22 i/f drop on random is the key result. Random floats have ~9 fraction
# digits so the original while(>= 8) fired once (trivially, no back-edge), yet
# Clang still treated SWAR constants as loop-body rematerializations under the
# high register pressure of the inlined findmax_ffc context.
#
# Converting to a while(>= 16) loop that fires zero times for random, followed
# by a plain if(>= 8) for the one-shot 8-digit block, removes the loop context
# entirely. Clang then sees the SWAR code as a straight-line block with no loop
# back-edges, and allocates registers optimally rather than conservatively.
# Constants (mul1, mul2, 100000000) are kept live throughout the linear path.
#
# Canada benefits from the 2x loop eliminating the back-edge for 16-digit
# fractions (one 16-digit iteration vs two 8-digit iterations), reducing
# SWAR constant rematerialization from 2 rounds to 1.
#
# EXP-043 failure was expected: it only renamed constants but Clang still
# treated them as compile-time constants rematerialized inside the while loop.
# EXP-044's change works because it removes the while loop context itself.
#
# GCC auto-unrolls the original while(>= 8) naturally (23% larger binary).
# Manual unrolling conflicted with GCC's strategy (tested: universal unroll
# caused canada −5.7% and mesh −4.2% for GCC). The Clang-only #ifdef preserves
# GCC's existing well-optimized behavior.
#
# Updated Clang-GCC gap:
# random:  1613 vs 1933 = −16.6% (was −21%)
# canada:  1420 vs 1737 = −18.2% (was −21%)
# mesh:    1395 vs 1741 = −19.9% (was −21%)
# i/f gap:
# random:  223.02 vs 219.04 = +3.98 (was +25.98; nearly closed!)
# canada:  198.17 vs 190.70 = +7.47 (was +17.20)
# mesh:     98.50 vs  83.92 = +14.58 (was +18.04)
#
# Decision: ACCEPTED
